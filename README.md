# 💥 Chain Reaction — Online Multiplayer

เกม Chain Reaction พร้อมระบบออนไลน์ สร้างห้อง + แชร์รหัส 4 ตัว

---

## 🚀 Deploy บน Railway (ฟรี)

### ขั้นตอน

```bash
# 1. ติดตั้ง dependencies
npm install

# 2. ทดสอบ local
npm start
# เปิด http://localhost:3000
```

### Deploy Railway

1. ไปที่ **railway.app** → Login ด้วย GitHub
2. กด **"New Project"** → **"Deploy from GitHub repo"**
3. เลือก repo นี้
4. Railway จะ detect `package.json` และ deploy อัตโนมัติ
5. ได้ link เช่น `https://chain-reaction-production.up.railway.app`

## 🌐 เล่นออนไลน์บน GitHub Pages (ไม่ต้องมีเซิร์ฟเวอร์)

GitHub Pages รันโปรแกรมไม่ได้ จึงให้ **เบราว์เซอร์ของคนสร้างห้อง (โฮสต์) ทำหน้าที่เซิร์ฟเวอร์แทน** โดยใช้ Firebase Realtime Database เป็นทางส่งข้อมูลระหว่างผู้เล่น
กติกา การจับเวลาตา การเลือกการ์ด และการกลับเข้าห้องด้วย token ใช้โค้ดชุดเดียวกับเซิร์ฟเวอร์จริง (`server/game-server.js`)

### ตั้งค่า (ทำครั้งเดียว)

1. **Firebase → Authentication → Sign-in method** → เปิด **Anonymous**
2. **Firebase → Realtime Database → Rules** → วางเนื้อหาของ [`database.rules.json`](database.rules.json) แล้วกด **Publish**
3. ใส่ค่า Firebase ของโปรเจกต์ใน [`client/fb-config.js`](client/fb-config.js) (ค่าในไฟล์เป็นของโปรเจกต์ปัจจุบัน)
4. **GitHub → Settings → Pages → Build and deployment → Source = GitHub Actions**
5. push เข้า `main` → workflow [`pages.yml`](.github/workflows/pages.yml) เผยแพร่เอง ได้ลิงก์ `https://<user>.github.io/<repo>/`

เปิดจาก `npm start` หรือ Railway จะใช้ socket.io ตามเดิม ไม่แตะ Firebase

### ความปลอดภัยของโหมด Firebase

ในโหมดนี้ใครก็ตามที่เปิดหน้าเว็บจะได้บัญชีนิรนาม (Anonymous) และเขียนลงฐานข้อมูลได้ตามที่ Rules อนุญาต สิ่งที่กันไว้แล้ว:

| เรื่อง | กันอย่างไร |
|---|---|
| จองรหัสห้องค้างไว้ไม่ให้ใครสร้างห้อง | เวลาใน `hosts/{code}` เป็นเวลาของ server เท่านั้น (ตั้งล่วงหน้าไม่ได้) · โฮสต์ต้องต่ออายุทุกนาที · ไม่ต่ออายุเกิน 5 นาทีถือว่าว่าง · หนึ่งบัญชีถือได้ทีละรหัสเดียว (`hostOf/{uid}`) |
| ถล่มโฮสต์ด้วยคำสั่งจำนวนมาก | โฮสต์รับเฉพาะคำสั่งในรายการที่กำหนด · sid ที่ไม่รู้จักต้องเริ่มด้วยการเข้าห้อง · จำกัดอัตราต่อบัญชี (40 ข้อความแรก แล้ว 20/วินาที) เกินแล้วบล็อก 60 วินาที · ไม่เกิน 3 การเชื่อมต่อต่อบัญชี และ 12 ต่อห้อง · คิวค้างเกิน 300 ทิ้งทั้งคิว |
| ข้อมูลห้องค้างเมื่อโฮสต์แครช | `onDisconnect` ลบทั้ง `rooms/{code}`, `hosts/{code}` และ `hostOf/{uid}` · โฮสต์ใหม่ล้างของค้างก่อนเริ่มฟังเสมอ |
| ปลอมเป็นผู้เล่นคนอื่น | Rules บังคับว่า `from` ต้องขึ้นต้นด้วย uid ของคนเขียน และต้องมี `presence` ของ sid นั้นในห้องก่อน · แต่ละคนอ่านได้เฉพาะกล่องขาออกของตัวเอง |

**สิ่งที่ต้องทำเองใน console (ผมแก้จากรีโปให้ไม่ได้):**

1. **Publish Rules ใหม่ทุกครั้งที่ไฟล์ `database.rules.json` เปลี่ยน** — Realtime Database → Rules → วางทั้งไฟล์ → Publish (Rules รุ่นก่อนใช้กับโค้ดรุ่นนี้ไม่ได้: สร้างห้องจะขึ้นว่า Rules ไม่อนุญาต)
2. **จำกัดที่มาของ API key** — Google Cloud console → APIs & Services → Credentials → Browser key → Website restrictions: ใส่ `https://<user>.github.io/*` (และ `http://localhost:*` ถ้าจะลองในเครื่อง)
3. **App Check (แนะนำ ถ้าเปิดให้คนทั่วไปเล่น)** — ดูวิธีใน `client/fb-config.js` · กัน bot ที่ไม่ได้เปิดผ่านหน้าเว็บนี้ ซึ่งเป็นสิ่งเดียวที่กันการสร้างบัญชีนิรนามจำนวนมากมาจองรหัสได้จริง
4. แพ็กเกจฟรี (Spark) มีเพดานการเชื่อมต่อพร้อมกันและปริมาณข้อมูลต่อเดือน — ดูหน้า Usage ถ้ามีคนเล่นเยอะ

**ยังไม่ได้ทดสอบกับ Firebase จริง:** ชุดทดสอบใช้ฐานข้อมูลจำลองในหน่วยความจำ ซึ่งจำลอง Rules เฉพาะส่วน `hosts` / `hostOf` (เครื่องที่ใช้พัฒนาไม่มี Java จึงรัน Firebase emulator ไม่ได้) หลัง Publish Rules ให้ไล่ตามรายการนี้หนึ่งรอบ:

- [ ] เปิดสองแท็บ: สร้างห้อง → เข้าห้องด้วยรหัส → เริ่มเกม → เล่นจนจบ (ทุกคำสั่งต้องไม่ขึ้น "Rules ของ Firebase ไม่อนุญาต")
- [ ] แขกรีเฟรชกลางเกม → กลับเข้าที่นั่งเดิม
- [ ] โฮสต์ปิดแท็บ → แขกถูกพากลับเมนู · ในแท็บ Data ของ console ต้องไม่เหลือ `cr/rooms/{code}`, `cr/hosts/{code}`, `cr/hostOf/{uid}`
- [ ] โฮสต์เปิดห้องค้างไว้เกิน 2 นาที → ดูใน console ว่า `cr/hosts/{code}/t` เปลี่ยนทุกนาที
- [ ] Rules Playground (ปุ่มในแท็บ Rules): จำลอง `set` ที่ `cr/hosts/1234` ด้วย `{ "host": "<uid อื่น>", "t": 9999999999999 }` → ต้อง **ถูกปฏิเสธ**
- [ ] Rules Playground: จำลอง `get` ที่ `cr/rooms/1234/in` ด้วยบัญชีที่ไม่ใช่โฮสต์ → ต้อง **ถูกปฏิเสธ**

### ข้อจำกัดของโหมดนี้

- **โฮสต์ต้องเปิดแท็บค้างไว้ตลอดเกม** — ปิด/รีเฟรชแท็บโฮสต์ = ห้องปิด (แขกจะถูกพากลับเมนูหลังรอครู่หนึ่ง) แท็บของแขกปิด/รีเฟรชได้ กลับเข้าที่นั่งเดิมได้
- เบราว์เซอร์ชะลอตัวจับเวลาของแท็บที่ซ่อนอยู่/มือถือล็อกจอ → นาฬิกาตาของห้องอาจเดินช้าลงถ้าโฮสต์สลับแท็บ ควรให้โฮสต์เปิดแท็บนั้นไว้หน้าจอ
- โฮสต์เป็นคนตัดสินกติกา จึงโกงได้ในทางทฤษฎี (แขกโกงไม่ได้ เพราะส่งได้แค่คำสั่ง) เหมาะกับเล่นกับเพื่อน ไม่เหมาะกับแข่งจริงจัง
- รหัสห้องมี 4 หลัก จองผ่าน Firebase จึงไม่ซ้ำกัน · หนึ่งบัญชี (เบราว์เซอร์) เป็นโฮสต์ได้ทีละห้อง: เปิดห้องใหม่จากอีกแท็บ = ห้องเดิมปิด
- โฮสต์หลุดเน็ตชั่วครู่: ห้องและเกมยังอยู่ในแท็บของโฮสต์ แขกจะกลับเข้าที่นั่งเดิมเองเมื่อโฮสต์ต่อกลับมา

### ทดสอบ

```bash
npm test         # กติกา/การ์ด, socket.io, โหมด Firebase (ฐานข้อมูลจำลองในหน่วยความจำ)
npm run test:fx  # จังหวะเอฟเฟกต์ในเบราว์เซอร์จริง (ต้องมี Chrome; ข้ามเองถ้าไม่มี)
```

Rules และ SDK จริงของ Firebase ทดสอบอัตโนมัติไม่ได้ ต้องลองเองหลังตั้งค่า: เปิดสองแท็บ แท็บแรกสร้างห้อง แท็บที่สองเข้าห้องด้วยรหัส แล้วเล่นจนจบ
